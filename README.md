# 角色动作编排引擎

纯 Python 实现，先覆盖动作播放、条件状态切换和平滑混合；动作资源与角色实例分离，方便多个角色共用同一批片段。

## 模块

- `animation_engine/clip.py`：不可变关键帧动作、命名标记（可携带外部事件）、循环边界采样、根移动分段精确积分。
- `animation_engine/player.py`：每个角色独立的播放游标、速度、过渡冻结快照、标记相位对齐、事件队列、反向播放/跳转与播放状态存取。
- `animation_engine/state_machine.py`：命名状态和基于条件回调的状态切换。
- `animation_engine/library.py`：内置 idle/walk/run 与短动作 `step_dodge`。

## 连续性设计

过渡不是简单平均两个姿态：新切换会先冻结“当前混合结果”的关节值、根速度和角速度，再向目标片段做 smoothstep 混合。根部位移按混合权重对速度积分，循环边界和关键帧边界自动分段，因此在旧过渡未完成时再次切换不会产生位置跳变。

播放状态包含目标片段、局部时间、播放速度、根部位置/朝向、混合已用时间和冻结快照。保存后用新的播放器载入，再以相同时间步进独立采样，会与未中断播放得到一致结果。

## 标记与事件

- 片段是不可变资源：`Marker(name, t, event=None)` 挂在片段时间轴上，可被任意数量角色共享；相位和事件触发进度只存在于各角色的播放器游标中，互不影响。
- 相位同步切换：`transition_to(..., sync_markers=((源标记, 目标标记),))` 或在 `Transition` 上配置。目标入口时间自动偏移，使目标标记对齐当前“最近一次源标记 + 相位差”（如走路接跑步的接地脚），循环片段按周期取最近出现点，非循环片段钳在片段时长内。
- 事件触发规则：事件在播放“向前越过”标记瞬间进入角色事件队列，由 `drain_events()` 取走。判定区间为半开区间 `(旧游标, 新游标]`，因此入口时刻上的标记不算触发；循环片段每个周期各触发一次。
- 大步推进与逐帧推进等价：根位移、姿态、事件序列只依赖游标的起点和终点（内部按关键帧/循环边界/混合结束点分段积分），单步 0.3 秒与 30 步 0.01 秒结果一致。
- 混合中再次切换：已取走的事件不会重放；已触发但尚未 `drain_events()` 取走的事件保留在队列中继续交付；新目标的事件游标从实际入口时间开始，入口之后的标记照常触发，入口之前（含入口时刻）的标记视为已经过而不会凭空补放。
- 保存/恢复包含事件游标（即局部时间、混合起点 `episode_start`）和未交付队列，恢复后继续推进不会重复也不会漏放。

## 反向播放与跳转

- 反向播放通过负 `dt` 或负 `speed` 显式表达：时间轴向回移动，跨段积分取负，根部位置/朝向沿原路退回；反向移动**不触发任何事件**，越过的事件标记会被重新武装，之后再次正向越过时正常触发。
- 非循环片段正向钳在片段末尾、反向钳在 0；循环片段回绕播放。混合中的反向最多退到本次混合起点（`episode_start`），不复活进入混合前的旧片段。
- `seek(cursor, fire_events=False)` 为显式跳转：立即取消混合并丢弃冻结快照，只改变相位，根部位置/朝向不变。正向跳转默认不补发事件（避免跳转后误触攻击判定），传 `fire_events=True` 时按顺序交付途中所有事件；反向跳转永不触发并重新武装标记。
