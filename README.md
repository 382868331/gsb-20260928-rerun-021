# 角色动作编排引擎

纯 Python 实现，覆盖动作播放、条件状态切换、平滑混合、标记（marker）同步与外部事件；动作资源与角色实例分离，多个角色共用同一批片段时各自保留相位与事件进度。

## 模块

- `animation_engine/clip.py`：不可变关键帧动作与标记、循环边界采样、根移动分段精确积分（支持反向）。
- `animation_engine/player.py`：每个角色独立的播放游标、速度、事件进度、过渡冻结快照与播放状态存取。
- `animation_engine/timing.py`：每角色可变的速度段编排（`SpeedSchedule`），支持落脚放慢/腾空加快与目标步态时长。
- `animation_engine/footsteps.py`：不平地面上的逐脚接触约束（`FootstepTracker`）：可编辑地面、每只脚独立的接触区间与可落脚片段、未满足原因与滑动量报告、保持/调整步幅方案对比。
- `animation_engine/state_machine.py`：命名状态和基于条件回调的状态切换。
- `animation_engine/library.py`：内置 idle/walk/run（含 `foot_down` 接地脚标记）、`step_dodge` 与带 `windup`/`hit` 事件的 `attack`。

## 标记与事件

标记是共享片段上的只读时间点（`Marker(t, name, payload)`），事件进度（是否已触发）属于每个角色的播放器：

- `request_transition(..., sync_marker="foot_down")` 延续当前接触阶段：计算源片段自最近一次同名标记经过的时间偏移，并按两侧接触周期之比缩放后带入目标片段——异长循环保持*相位*一致（1.2s 周期走到 0.72s 切入 0.6s 周期落在 0.36s；等长周期等同于携带绝对偏移，走路 0.63s 前接地则跑步也从接地后 0.63s 起步），而不是吸附到标记本身造成脚步相位跳变；进入瞬间停在标记上不触发事件。非零标记、循环边界两侧与反向播放时间使用同一套模运算，偏移含义一致。
- 每次切换记录切换前后的接地快照（片段、局部时间、标记后偏移、跨步进度、是否处于接地支撑相），通过 `transition_history()` 回放；快照随 `save_state()` 保存、`load_state()` 恢复。
- 大步推进与逐帧推进使用同一套标记穿越枚举（半开区间 `(t0, t1]`），事件顺序一致、不丢不重；`pop_events()` 取出外部事件（如攻击在 `hit` 标记处造成伤害）。
- 循环片段的标记每一圈至多触发一次（用圈号区分）；非循环片段整个播放期内只触发一次。
- 混合尚未结束时切换第三个动作：当前混合结果被重新冻结后向第三个片段继续 smoothstep，新片段开始新的播放代（generation），切换中途改变播放速度同样只影响后续时间；旧片段尚未到达的标记随片段取消，不会凭空补发，已经进入队列的外部事件保留并照常投递，根位移与脚步事件不重不漏。大步推进、逐帧推进（事件走同一套半开区间穿越枚举）以及在混合中途保存再恢复到新播放器继续，三者的姿态、根部位移与事件顺序一致。
- 保存/恢复包含 generation、已触发表和待投递事件，因此混合中存档后事件序列与未中断播放一致。

## 变速段编排

- `animator.set_speed_schedule([(end, rate), ...], target_duration=...`) 在当前片段上安装每角色独立的速度段：段以片段局部时间的终点划分并覆盖整个周期（循环片段每圈重复），`rate` 为相对速率，例如 `[(0.5, 0.5), (1.0, 2.0)]` 让支撑相前半圈放慢、摆动相后半圈加快；`target_duration` 把整圈步态拉伸到指定的墙钟时长。
- 混合进行中修改速度安排只影响尚未播放的时间：接触标记的到达时刻与脚步事件按新安排触发，已经触发的事件不回写；每圈的根位移由片段本身决定，与匀速播放一致。
- 速度安排随 `save_state()`/`load_state()` 保存恢复；切换到其他片段时安排不随迁（段定义针对具体片段时间轴），带 `sync_marker` 的中途转向仍按相位延续。

## 反向播放与跳转

- `update(dt)` 接受负 `dt`：姿态和根位移精确回退（根积分对有符号时间分段），但反向穿越标记**不触发事件**；恢复正向播放后，已触发过的标记不会重放。
- 混合中反向立即取消混合，按目标片段回退。
- `seek(t)` 是显式跳转：取消进行中的混合、不做姿态平滑，跳过区间内的标记既不补发也不标记为已触发；已触发记录保留，回跳再正向经过不会重放。
- 非循环片段在首尾钳制，不会越过端点播放。

## 落脚约束与地面变化

`FootstepTracker` 包在播放器外面：每次 `tracker.update(dt)` 先推进玩家，再按当前片段的步态相位推导每只脚的落地/抬脚事件。地面由 `Terrain`（若干 `GroundSegment(id, x0, x1, height)`，可随时编辑）描述；每只脚用 `FootSpec` 指定接触区间（步态周期内的相位范围）、期望落点的前移量 `stride_offset`、允许落脚的片段 `allowed_segments` 和最大台阶高度 `max_step_height`。

- 脚进入接触区间时必须落地：落点取穿越时刻的根位置加前移量，检查该处是否有地面、片段是否被允许、与上一次确认落点的高差是否超限。三只检查任一失败都记为 `unsatisfied` 并写明原因（`no_ground` / `segment_not_allowed` / `step_too_high`），不会假造落地，也不会锁死整个角色——根继续推进，失败的脚按被拖行的距离累计 `slip`。
- 处于接触阶段的脚保持在确认落点不动（滑动量为 0），身体和根继续推进；只有腾空后才允许选择下一个落点。
- 已确认的接触记录是只追加的历史：中途改速度段、目标周期或切换动作只重排尚未发生的落脚时刻；事后编辑地面也不会改写历史（记录保存的是当时的快照）。反向播放既不产生也不删除接触，与事件规则一致。
- 落点位置与时刻是片段时间区间的纯函数（根位移用 `integrate_root` 精确积分、墙钟时间按速度段解析累积），因此分段小步推进与整段大步重放得到完全相同的接触记录；混合中转向第三个动作、经过循环边界时，每只脚的接触状态各自独立且可解释。
- `contact_report()` 给出每只脚当前的状态、实际接触位置、滑动量与未满足原因；`contact_history()` 返回已闭合的接触记录。
- `compare_plans(n)` 在地面高度或可落脚范围不足时并排给出两个方案：`keep` 保持原步幅（无法达到的落点保留未满足状态），`adjust` 在限定幅度内缩放后续步幅以够到允许片段；两者都只是模拟，不改实现时状态。
- 保存时一只脚着地、另一只脚腾空也没关系：`save_state()`/`load_state()` 分别保存各自的脚状态与活跃记录，重开后延续各自状态，与未中断播放的接触记录一致。

## 地形观测版本与历史重解释

地形知识以可登记、可撤回的观测版本增长：`terrain.register_observation(segments, note=None)` 提交一次补测（填入新片段补缺口，或以同 id 片段修订高度），返回从 1 开始的版本号；观测按登记顺序叠加在基础层之上，`terrain.snapshot(version)` / `height_at(x, version)` 可复现任意历史版本，`retract_observation(version)` 撤回某次补测且其余版本号保持稳定。

- 每条落脚记录都盖章当时的 `terrain_version` 与参考高度作为依据；登记新观测默认只影响未来落脚，绝不回写历史。
- `tracker.reinterpret(start, end, version=None)` 用指定（默认最新）地形版本重新评估该墙钟区间内**未满足**的落脚：结果追加到记录的 `interpretations`，原记录保持原样。已确认的支撑是冻结的——不会被静默移动，只在返回值的 `frozen` 计数中报告。
- 原始记录经 `contact_history()` 查询（保留当时的 no_ground 依据），最新解释经 `interpreted_history()` 查询（含 `basis_reason` / `basis_terrain_version` 与原依据对照）。
- `tracker.retract_observation(version)` 撤回观测并丢弃基于它的解释，受影响的待定记录自动回落到先前解释或原始待定状态，无关步态不变。
- 回跳（反向播放或 seek）再前进不会重复产生接触：tracker 按步态相位水位线去重，与播放器事件规则一致；水位线、解释记录与地形观测都随 `save_state()`/`load_state()` 保存，连续运行、事件间存档重开、回跳再前进三种方式得到完全相同的落脚序列。

## 冲突补测批次与按段解释

相互矛盾的多批补测可以同时保留：`terrain.register_observation(segments, batch="survey_a")` 给观测打上批次标签，默认（全叠加）视图里最新登记生效，但 `terrain.snapshot(batch=...)` / `height_at(x, batch=...)` 只叠加基础层与指定批次，任一批次都能单独复现，`terrain.batch_versions(batch)` 列出该批存活的版本号。

- `tracker.reinterpret(start, end, batch=...)` 按墙钟时间段选择用哪一批补测解释待定落脚：角色跨越缺口并中途变速时，可对缺口前段用一批、后段用另一批分别解释，比较结果后每段只采用其中一批；每条解释都记录来源（`batch` 与 `terrain_version`），经 `interpreted_history()` 查询。
- 已确认的支撑始终是冻结的：最新登记的高度（哪怕把脚下地面改写成别的值）只计入返回值的 `frozen`，绝不回写历史；批次未观测到的位置继续保持待解释（`no_ground` / `unsatisfied`），不会被强行解释。
- `tracker.retract_batch(batch)` 撤回整批观测，只丢弃依赖该批的解释，受影响记录回落到先前解释或原始待定状态；其他批次的选择与旧依据原样保留。`retract_observation(version)` 仍按单版本撤回。
- 未决冲突随 `save_state()`/`load_state()` 完整保存：存档重开后再倒放、正放，记录数量、解释来源（批次）与连续播放结果完全一致；重开后批次仍可撤回。

## 局部撤回与再次确认

复核者可以只撤回某段墙钟区间内的采用决定，而不撤回整个补测批次：`tracker.reinterpret(start, end, batch=..., note=...)` 登记决定时记下操作者说明，`tracker.retract_interpretation(start, end, batch=None, note=None)` 按区间撤回（可选限定只撤回采自某批的决定），观测本身保持登记，同批覆盖的其他区间确认不受影响。

- 每次局部撤回只弹出受影响记录的最新解释，记录回落到先前解释或原始待定状态；被撤回的决定（含原操作者说明、来源批次与所依据的 `terrain_version`）连同撤回说明一起保存在记录的 `retracted` 列表中，`tracker.retraction_log()` 汇总全部撤回轨迹。
- 撤回后的区间可再次 `reinterpret` 确认（可换用矛盾批次）；仍未被任何观测覆盖的位置保持 `no_ground` 待定，不会自动获得支撑。
- 撤回轨迹随 `save_state()`/`load_state()` 完整保存：同一批覆盖两段落脚时，只撤回其中一段、登记矛盾观测、保存重开再往返播放，另一段的确认不丢失，撤回日志与连续运行一致。

## 连续性设计

过渡不是简单平均两个姿态：新切换会先冻结“当前混合结果”的关节值、根速度和角速度，再向目标片段做 smoothstep 混合。根部位移按混合权重对速度积分，循环边界和关键帧边界自动分段，因此在旧过渡未完成时再次切换不会产生位置跳变。

播放状态包含目标片段、局部时间、播放速度、根部位置/朝向、混合已用时间和冻结快照。保存后用新的播放器载入，再以相同时间步进独立采样，会与未中断播放得到一致结果。
